1. Goals & non-goals

Success bar

  • Word-perfect recitation, including the reference (AWANA standard: the kid can say "John 3:16 — For God so loved the world… — John 3:16" unprompted). Games that only produce recognition ("I know that word goes next when I see it") do not meet the bar by themselves.
  • Cadence: one verse per week per the Sparks handbook sections. The app should make that week's verse stick and keep old ones warm.
  • Audiences: HangGlider = Kindergarten (pre/early reader — audio-first, text shown but never required), WingRunner = 1st grade (emerging reader), SkyStormer = 2nd grade (reader — can handle text-heavy mechanics like first-letter cues).
  • Settings: home solo, home with a parent, classroom/Sunday school (group games), and car/on-the-go. Session length varies — every game must deliver value in one 2–4 minute round with natural stopping points.

Constraints (unchanged from today)

  • Static site, no build step, vanilla ES modules, GitHub Pages. The only new asset class is audio files (see §4).
  • No failure states. Wrong answers wiggle and invite another try (docs/GAME_SPEC.md rule 1). This is pedagogically correct for K–2: anxiety suppresses memory consolidation, and low-stakes retrieval is what makes the testing effect work.
  • Offline: degrade gracefully. Online gets the best audio; offline falls back down the audio chain (song file → generated voice file → device speech), with committed files cacheable by a future service worker.
  • All four translations (NIV84, ESV, KJV, NKJV) stay. The owner will supply verse songs for all four translations.

Non-goals

  • No accounts, no server, no analytics. Progress stays in localStorage.
  • No spaced-repetition scheduler (decided: a simple per-book review playlist instead — see §9).
  • No locked progression. The Mastery Ladder is suggested, never enforced — kids can play anything anytime.

2. Pedagogy foundation

Every verdict in §5 traces back to one or more of these principles (plain language, deliberately no academic citations). When designing or modifying a game, check it against this list.

#PrincipleWhat it meansWhere it shows up in this plan
P1Retrieval practice (the testing effect)Pulling a memory out strengthens it far more than putting it in again. Re-reading/re-hearing feels productive but is weak; being made to recall is what builds durable memory.The whole Ladder; recall-gating the arcade games; fading support on builders; Echo Chamber; Disappearing Verse is already this.
P2Recall > recognitionPicking the right word out of a lineup (recognition) is a much shallower act than producing it from nothing (recall). A kid can win every recognition game and still be unable to say the verse.Why the 7 tap-the-next-word builders and Memory Match are only Stage-1/2 tools; why ⭐⭐ and ⭐⭐⭐ require production, not selection.
P3Expanding cloze (progressive deletion)Hiding a little more of the text each round — while the learner fills the gaps — is the classic, extremely effective verbatim-memorization drill ("whiteboard method").Disappearing Verse (already gold standard); fading-support system; First-Letter Trail; Sticker Quest's see→peek→brave ladder.
P4Spaced / distributed practiceTwo short practices on different days beat one long one. Old verses decay without occasional touches.Per-book Review chips; gentle practice-day streaks; the win screen suggesting "review an old verse".
P5Dual coding (words + pictures)Pairing verbal content with a visual anchor gives memory two routes back to the same content.Draw & Tell (phrase→emoji/drawing); Puzzle Pieces' reveal picture; garden/trophy imagery tied to specific verses.
P6Melody & rhythm carry verbatim textKids remember songs word-perfect for years with no effort. Melody constrains word order and prosody, which is exactly what verbatim memorization needs.Sing-Along Stage built on the owner's per-verse song recordings (all four translations); Karaoke hooks the same audio.
P7ChunkingWorking memory holds 3–5 items; phrases are the natural unit. Learn phrase-by-phrase, then chain phrases (cumulative rehearsal: 1, 1+2, 1+2+3…).Existing ctx.chunk use everywhere; Echo Chamber's cumulative chain; Hot Potato's phrase turns.
P8Enactment & productionSaying it out loud (and doing an action with it) encodes more strongly than silent reading or tapping. The mouth is part of the memory.Every "say it, then tap ‘I said it!’" step (Disappear, Stickers, Karaoke, Echo Chamber); group choral games; the Recitation module.
P9Desirable difficulty, zero punishmentMemory grows when retrieval takes real effort — but for K–2 the effort must never read as failure. Struggle → hint → success, never struggle → game over.Peek buttons that cost stars but never block; mercy mechanics; hard modes redefined as more memory demand, not more speed (§9).
P10Overlearning & varied practiceKeep practicing past the first success, in varied forms and moods — variety re-engages attention and generalizes the memory beyond one context.Verse Spinner's silly recitation styles; the Ladder offering several games per verse; encore sections.
The core diagnosis of the current app: 13 of the 20 games are recognition games (P2) — the verse is always visible or the answer is always in a lineup. They're great exposure and fun, but a kid can 3-star an entire book without ever once producing the verse from memory. The redesign keeps their themes and fun, and rewires the star economy + game loops so that production (P1, P8) is what earns mastery.

3.2 Stars = mastery stages (progress schema v2)

Stars stop meaning "played a game well" and start meaning "how well do I know this verse":

  • ⭐ Built it — completed any Stage-1 or Stage-2 game for this verse.
  • ⭐⭐ Recalled it — completed a Stage-3 game with real memory demand met (e.g., Disappearing Verse with ≤1 peek, Echo Chamber chain complete, a builder at full fade with ≤1 mistake).
  • ⭐⭐⭐ Recited it — verified word-perfect recitation including the reference via the Recitation module (§8). This is the only way to earn the third star.

Migration: existing sparksArcade.v1 stars are honest about the old economy: any verse with stars > 0 migrates to stage 1 (⭐). Kids keep visible progress; nobody keeps an unearned ⭐⭐⭐. Stars remain monotonic (never go down). Per-game performance (mistakes/peeks) still drives in-game celebration messages, but not the star count.

4. Audio engine — fixing the creepy TTS

4.1 Why it's creepy today

All speech is speechSynthesis configured in js/lib/engine.js:90-116: rate 0.85, pitch 1.1, voice = first English voice whose name matches female|child|kid|samantha|zira. On devices without a good voice this lands on a robotic default, made worse by the artificially raised pitch and slowed rate — the uncanny "robot pretending to be a kid" effect. It also never sets utter.lang, doesn't handle onerror, and auto-speaks on mount without a user gesture (silently dropped on iOS Safari).

4.3 File layout, naming, compression S

audio/
  songs/<translation>/<ref-slug>.m4a     e.g. audio/songs/niv84/john-3-16.m4a
  read/<translation>/<ref-slug>.m4a      generated TTS (B) and/or human (D) — same slot
  • ref-slug: lowercase, non-alphanumerics → dash, collapse repeats: John 3:16 → john-3-16, 1 Corinthians 15:3-4 → 1-corinthians-15-3-4, John 3:14a → john-3-14a. Implement once as refSlug(ref) in js/lib/audio.js; book-list pseudo-verses use their key (nt-1, ot-all, facts).
  • Compression spec: mono, AAC in .m4a (universally playable incl. iOS; do not use Opus/webm — Safari support is inconsistent), 64 kbps for spoken word (56 kbps for the long lesson/story narrations), 96 kbps for songs, loudness-normalized to ≈ −16 LUFS. Budget revised now that the full Awana handbook audio is committed (§4.7): verse clips ≈ 30 MB, lessons/stories ≈ 60–90 MB — target ≤ 150 MB total committed audio, every file far below GitHub's 100 MB per-file limit, all lazy-loaded so app start-up cost is zero. Reference command: 
    ffmpeg -i in.mp3 -ac 1 -b:a 96k -af loudnorm=I=-16:TP=-1.5 out.m4a
  • Lazy loading: nothing preloads at app start. The verse screen preloads (with preload="auto") only the current verse's song + read file. One shared <audio> element; navigation stops it (extend teardownGame() in js/app.js:22-28).

4.4 Audio manifest S

No network directory listing on a static site, so a committed manifest says which files exist. Generated, never hand-edited:

// js/data/audio-manifest.js  (GENERATED by tools/build-audio-manifest.mjs — do not edit)
export const AUDIO = {
  read:  { common: { 'NT-1': {…} },                       // translation-independent book lists
           niv84: { 'John 3:16': { file: 'audio/read/niv84/john-3-16.m4a', duration: 14.1 } }, … },
  handbook: { hg: [ { file, duration, type: 'lesson'|'story', title, section } ], wr: […], ss: […] },
  songs: { common: { 'nt-books-song': {…} },               // Awana book-list songs
           niv84: { 'John 3:16': { file: 'audio/songs/niv84/john-3-16.m4a', duration: 62.4,
                                    timings: null /* or [ [word, startSec], … ] */ } }, esv: {…}, … },
};

tools/build-audio-manifest.mjs (node, dev-only like the tests — implemented): reads tools/awana-track-map.json plus files on disk, probes durations with ffprobe, picks up owner-added song files by ref slug, writes the module. Read lookup for (ref, translation) checks the translation table first, then read.common. Run manually after adding audio; documented in README.

4.5 Player module js/lib/audio.js M

playVerse(verse, { kind: 'sing' | 'read' | 'auto' })  // resolves via manifest + active translation,
                                                      // falls back to speak() when no file; returns
                                                      // { source: 'song'|'file'|'tts', el|utterance }
stopAudio()                                           // stops file audio AND speechSynthesis
onWordTick(cb)                                        // fires per word when timings exist (Sing-Along);
                                                      // falls back to even-split between 2% and 95% of duration
  • Exposed to games as ctx.audio; ctx.speak() is re-pointed internally so existing games get better audio with zero changes: a no-arg ctx.speak() becomes playVerse(verse, {kind:'read'}); ctx.speak(someText) for dynamic fragments (chunks, single words) still uses Web Speech.
  • iOS unlock: first user gesture anywhere (there's always a tap — Play button) primes the shared audio element and speech synthesis. Auto-speak-on-mount stays, but routes through the primed element so it actually plays.

4.6 Web Speech tuning (the fallback, de-creepified) S

Changes to speak() in js/lib/engine.js:

  • Voice ranking (replace the name-regex): prefer, in order: names containing natural|neural|premium|enhanced with lang en; then well-known quality voices by exact name (Samantha, Google US English, Microsoft Aria, Microsoft Jenny); then any en-*; else default. Stop filtering for "female/child/kid" by name — quality beats gender-guessing.
  • Prosody: rate 0.9, pitch 1.0 (drop the artificial 1.1 — a major creepiness source), always set utter.lang = 'en-US'.
  • Phrasing: split input at sentence punctuation into a queued series of utterances — natural pauses without SSML (which Web Speech doesn't support).
  • Robustness: utter.onerror → fail silent + leave the 🔊 button available; retry pickVoice() once after voiceschanged; keep the LORD→Lord normalization and the cancel-before-speak barge-in.

4.7 Handbook audio ingestion — DONE (replaced the cloud-TTS plan)

Awana's parent-resources page hosts free handbook-audio ZIPs for all three books × all four translations — professional human recordings of every verse, plus the handbook lessons and Bible-story narrations. These were ingested in full, which removed any need for generated TTS voices.
  • What's committed: audio/read/<translation>/<ref-slug>.m4a (every handbook verse, 4 translations), audio/read/common/ (Bible book-list recitations, translation-independent), audio/handbook/<book>/ (lesson + story narrations, deduped — content is translation-independent), audio/songs/common/ (Books-of-the-Bible songs), docs/resources/ (Bible Biography PDFs).
  • Tooling: tools/awana-track-map.json maps every ZIP track → ref/lesson/story/song (with skip reasons for duplicates); tools/fetch-awana-audio.py re-downloads/converts anything missing (idempotent, needs ffmpeg); tools/build-audio-manifest.mjs regenerates js/data/audio-manifest.js.
  • Known gaps (fall back to tuned device speech, §4.6): FACTS (Bible-facts prose — never recorded) and 1 Thessalonians 4:16-17 combined (4:16 and 4:17 exist as separate clips). Also Psalm 23:1 and Psalm 23:2 share Awana's single combined clip.
  • Verse songs: the music albums are purchase/streaming-only (Catapult → Apple Music/Spotify/Amazon). Each book screen now links the active translation's album under "For grown-ups" (js/data/music-links.js); owner-purchased files still slot in per §4.8.

4.8 Song ingestion checklist (for the owner's mp3s)

  1. Name files by ref slug and drop into audio/songs/<translation>/ (see 4.3). A song that covers a combined ref (e.g. John 3:14-16) uses that combined slug.
  2. Run the ffmpeg normalize/compress one-liner (4.3) — or commit as-is and let a session batch-convert.
  3. Run node tools/build-audio-manifest.mjs; commit audio + regenerated manifest together.
  4. Optional, later, per song: add <slug>.timings.json ([["For",8.2],["God",8.6],…]) for word-accurate bouncing-ball highlighting in Sing-Along Stage. Without it the game uses even-split timing, which is acceptable.
  5. Partial coverage is fine at every step — any verse without a song simply hides its 🎵 affordances and Stage 1 falls back to Karaoke/read-along.

4.9 New features unlocked by the handbook audio

📻 Story Time NEW M — planned for P3

What
A listening corner: home-screen destination (#/stories) listing the ~50 professionally narrated Bible stories and character stories from audio/handbook/, grouped by book, each with a big play button, duration, and the section it belongs to. Section screens also surface "🎧 tonight's story" for their own section's narrations.
Why (pedagogy)
Narrative context is elaborative encoding — a verse tied to its story ("Noah And God's Promise" → 1 Peter 1:25) is easier to recall and means more. Also the single best car-ride feature: 5-minute stories, zero reading, zero screen demand.
Spec
Reads AUDIO.handbook from the manifest. Simple list UI reusing .card rows; one shared <audio> element with play/pause + a "keep playing the next one" toggle for car mode; remembers last-played per book in localStorage. Stops on navigation via teardownGame()-equivalent hook.
Acceptance
All handbook tracks playable; audio stops on route change; playable with screen locked (no wake-lock tricks — plain <audio> keeps playing on mobile).

🎧 Listen to the Lesson NEW S — planned for P4

What
Each section screen gets a small "🎧 Listen" chip when AUDIO.handbook[book] has lesson/story entries for that section — the handbook's own teaching segment ("S Is For Savior", "What Is A Missionary?") plays right where the kid is working on that section's verses.
Why
The lesson explains what the verse means — comprehension before memorization makes the memory stick (meaningful > rote encoding), and it's the same content a leader teaches at club.
Acceptance
Chip appears only for sections with mapped audio; plays/pauses inline; stops on navigation.

5.4 The seven builders — FIX via shared fading support

All seven share one flaw: the verse (or a guide strip) is always visible, so the loop is "match next visible word", pure recognition (P2). One engine-level fix upgrades all of them identically — the fading-support system (full spec §7.1): pass 1 shows the full guide, pass 2 shows first letters only, pass 3 shows blank slots. The kid's tap targets and the fun theme are untouched; only the guide fades. Completing a pass at first-letter or blank level with ≤1 mistake records a stage-3-worthy pass (⭐⭐ path without leaving their favorite game). Per-game work after the engine helper exists is S each and mostly mechanical — replace the game's own guide/preview element with ctx.guide(...).

🧩 Verse Scramble FIX Stage 2 S

Current
js/games/scramble.js — tap shuffled word tiles in order; preview strip always visible (even in hard, by design at :70). HG RJ1 + SS GJ1.
Fix
Fading support on the preview strip. Hard/encore starts at first-letter level. Note: the tile pool itself is already a partial cue (the words are all visible somewhere); that's acceptable at Stage 2 — ordering from a pool without a guide is markedly harder than copying a visible strip.
Acceptance
Pass 2+ shows first-letter guide; faded pass with ≤1 mistake records stage 3 credit.

Current
js/games/hopscotch.js — pick the next word from 2–3 choices; kangaroo hops the chalk court. WR GJ3.
Fix
It has no separate guide strip — the choices are the support. Fade differently: pass 2+ shows choice buttons as first letters; tapping speaks the full word (audio confirm). This makes the choice itself a recall probe.
Acceptance
Pass 2 choices are first-letter; tap speaks word; court/hop unchanged.

5.5 The arcade pair — FIX via recall-gating

🌧️ Falling Words FIX Stage 2–3 M

Current
js/games/falling.js — tap the next word among 3–4 falling tiles; caught words fill ghost slots. WR Rank.
Problem
Attention goes to the physics; the filled ghost strip + small tile count means reflex + elimination wins without processing the verse (P2 violation).
Fix — recall-gate (shared helper §7.2)
Each catch cycle becomes: (1) rain pauses at a cloud line, the ghost strip shows filled words then a pulsing blank — a 1.5–2 s "what comes next?" beat with optional audio prompt of the phrase so far; (2) tiles then fall wordless as raindrops for a moment; (3) words fade onto the drops and the kid catches the one they recalled. Peek button on the blank costs like Disappear's peeks. Later passes fade the filled ghost words to first letters (fading support composes).
Acceptance
Prompt beat precedes every drop cycle; peeks tracked; physics/respawn invariants (replacementWord, decoy uniqueness) intact; autoplay updated.

⚔️ Sword Drill Slash FIX Stage 2–3 M

Current
js/games/slash.js — fruit-ninja swipes on ballistic word tiles; waves of 6 words; hard hides the next-word preview. SS Rank.
Problem
Same as Falling Words, plus swiping rewards speed over thought.
Fix — recall-gate
Between waves, a "sword drill" moment: HUD shows the verse so far + pulsing blank, kid has a think-beat (2nd graders: first-letter hint appears after 3 s instead of the full-word glow at 6.5 s). Then tiles launch and the swipe frenzy is the reward for recall, not the task itself. Keep all anti-frustration systems (force-relaunch, anti-spam). Encore keeps hidden preview + adds first-letter HUD.
Acceptance
Think-beat gates each launch volley; hint ladder (3 s first letter → 6.5 s glow); swipe mechanics untouched.

🃏 Memory Match REPLACE S (removal)

Current

6. New game specs

All four follow the docs/GAME_SPEC.md module contract ({id, title, icon, tagline, howTo, mount(stage, ctx)}, cleanup function, .g-<id> style prefix, handle isList verses, call ctx.win once, no failure states).

🎶 Sing-Along Stage NEW Stage 1 M — js/games/singalong.js

Pedagogy
P6 (melody carries verbatim text), P3 (gap rounds), P8 (singing = production).
Placement
Not a section signature game — it's the universal Stage-1 row on every verse's ladder menu (when the active translation has a song file; otherwise the row falls back to Karaoke/read-along).
Loop
Round 1 — Sing along: song plays; word tiles highlight via ctx.audio.onWordTick (timings file if present, even-split fallback); a bouncing note leads the line. Kid just sings.
Round 2 — Fill the gaps: song plays but pauses automatically at 2–3 phrase boundaries; the next phrase's tiles flip face-down; kid sings the gap out loud, taps ▶ to hear it confirmed and continue.
Round 3 — Star performance: all tiles face-down; song plays; kid sings the whole thing over the track (K: word 1 of each phrase stays visible).
Grade tuning
K: 2 gaps in round 2, first words visible in round 3. 1st: 3 gaps. 2nd: gaps chosen at clause starts (hardest positions) and round 3 fully hidden.
Stars/stages
Completing round 1 = stage-1 credit (⭐). Rounds 2–3 are performance (self-reported by design, like Karaoke) — celebrate but don't award ⭐⭐.
Edge cases
No song file → game not offered (ladder shows fallback). isList verses: only if a list song exists (books-of-the-Bible songs are classic — supported, not required). Pause points come from timings when present, else even thirds.
Acceptance
Word highlight tracks audio within ±1 word (timed songs); gap pauses land between words; cleanup stops audio; autoplay strategy: tap-through.

🔊 Echo Chamber NEW Stage 3 M — js/games/echo.js (replaces Memory Match: HG RJ2 + SS GJ4 encore)

Pedagogy
P1/P2 (pure production), P7 (phrase chunks + cumulative chaining), P8 (aloud), audio-first so K pre-readers do real recall with zero reading.
Loop (standard, HG RJ2 and ladder rows)
A friendly parrot/cave theme. Per phrase (chunk of 3–4 words for K, 5–6 otherwise):
1. Hear: phrase speaks (read-file audio preferred); its word tiles glow in sequence as spoken.
2. Vanish: tiles flip face-down after a beat.
3. Echo: kid says the phrase out loud, then taps the big "I said it! 🦜" button; tiles flip back one-by-one while the audio replays as confirmation (kid self-checks — same trust model as Disappearing Verse).
4. Chain: after each new phrase, echo from the top: phrase 1, then 1+2, then 1+2+3 (cumulative rehearsal). Chain steps show only first-word cue tiles.
Peek = tap a face-down tile to flash it (1.5 s), counted like Disappear's peeks. Finale: echo the whole verse + say the reference (reference tile included in the final chain).
Encore mode (SS GJ4, ctx.hard)
Longer chunks (6–8), no glow-along on first hearing (listen only), peeks locked during the final full chain, reference required mid-chain not just at the end.
Stars/stages
Full chain with ≤1 peek → stage-3 credit (⭐⭐). Message references the echo: "The cave heard every word!"
Edge cases
isList: chunks of 3 book names, chain as normal (great for list order). 60+ word verses: cap the chain at the last 3 phrases + "from the top" only at the finale. No-audio environments: tiles glow with silent timing; game remains playable.
Acceptance
Chain grows cumulatively; peek counting matches Disappear's semantics; win once; autoplay strategy: tap "I said it!" through (order strategy).

🎨 Draw & Tell NEW Stage 3 M — js/games/drawtell.js

Pedagogy
P5 (dual coding), P1 (recall from picture cues), generation effect (choosing/creating the picture is itself encoding).
Placement
Ladder Stage-3 alternative for WingRunner/SkyStormer (readers get the most from phrase↔picture links); available to K with parent.
Loop — emoji mode (default)
Verse splits into 2–5 phrases.
1. Picture it: for each phrase (shown + spoken), kid picks 1 of 4 candidate emoji "that reminds you of it" (curated candidates per common word themes — love ❤️, world 🌍, believe 🙏, life 🌱, etc., from a keyword→emoji map in the module; fallback: generic scene emoji). Their choice matters, not correctness — no wrong answers here.
2. Tell it back: only the chosen emoji row remains, in order; kid says each phrase from its picture, tapping the emoji to confirm (tap reveals the phrase text + speaks it — a self-check, with reveals counted as peeks).
3. Shuffle: emoji shuffle; kid drags/taps them back into verse order, then tells the whole verse from pictures + says the reference.
Draw mode (optional toggle)
Replaces step 1's emoji pick with a finger-canvas per phrase (thick crayon stroke, 6 colors, clear button). Drawings render as the cues in steps 2–3. Stored per verse in localStorage as downscaled dataURLs (≤ 20 KB each, cap 5 phrases); "my drawings" persist for replays. Canvas is a plain <canvas> with pointer events — no libraries.
Stars/stages
Step 3 complete with ≤1 reveal → stage-3 credit (⭐⭐).
Edge cases
isList: pictures per book-name group of 3. Long verses: cap at 5 phrases (chunk larger). Storage full → draw mode falls back to emoji silently.
Acceptance
Emoji mode fully playable without drawing; reveals counted; drawings persist across sessions; autoplay: tap-through (order strategy on emoji picks + confirms).

🔤 First-Letter Trail NEW Stage 3 S–M — js/games/firstletter.js

Pedagogy
P3 (the first-letter cue is the classic, proven bridge from supported to free recall for verbatim text), P1, P9. Reader-dependent → SkyStormer-focused.
Placement
Ladder Stage-3 default for SkyStormer; offered to WingRunner late-year. Not shown for HangGlider.
Loop
A mountain-trail theme; the verse is stepping-stones along a path.
Level 1: full text shown; kid reads it aloud, taps each word as they say it (sets the tap-as-you-say rhythm; a hiker emoji walks the trail).
Level 2: words collapse to first letters (F G s l t w… — keep capitalization + punctuation: F for "For", G for "God"); kid says each word, tapping its letter. Tap-and-hold peeks the full word (1.5 s, counted).
Level 3: letters vanish to bare stones; only the reference remains at the trailhead. Say the whole verse tapping stone-by-stone, then say the reference at the summit flag. 🎉
Grade tuning / encore
Standard: levels 1→2→3, peeks allowed everywhere. Encore-style hard: start at level 2, peeks locked on level 3.
Stars/stages
Level 3 complete with ≤1 peek → stage-3 credit (⭐⭐). Level 2 complete → celebrate, no stage change.
Edge cases
isList: first letters of book names are a famously good drill — fully supported ("G E L N D…"). Long verses: trail scrolls horizontally by phrase (reuse Train Builder's auto-scroll pattern, train.js:186-199). Words with leading numerals ("1 Corinthians" in lists) show "1C".
Acceptance
First-letter rendering correct incl. punctuation + numerals; peek counting; summit reference step required; autoplay: order strategy (tap every stone).

7. Shared engine work

7.1 Fading-support system M

  • API: ctx.guide(words, opts) in js/lib/engine.js — returns a guide-strip element games mount wherever their current preview/hint lives, rendering each word at the current support level: 0 full text · 1 first letters · 2 blank slots. Handles lit/unlit ("done so far") styling, per-word update calls, and a shared peek interaction (tap a faded word to flash it, auto-counted).
  • Level selection: stored per verse+game in progress v2 (passes counter): pass 1 → level 0, pass 2 → level 1, pass 3+ → level 2. Grade defaults shift it: HangGlider caps at level 1 unless the kid opts into "super brave" via a toggle chip; SkyStormer encores start at level 1. A small chip on the game screen shows the level (🌕 🌗 🌑) and lets the kid change it freely — autonomy, no locks.
  • Stage credit: the engine (not each game) watches for "completed at level ≥1 with ≤1 mistake+peek" and records stage-3 credit via progress v2 — games just report mistakes/peeks as today via their existing counters passed to ctx.win (extend the payload: ctx.win({stars, message, mistakes, peeks}); engine maps to stage credit so per-game logic stays dumb).
  • Consumed by the 7 builders (§5.4) + Falling/Slash HUDs (§5.5). Update docs/GAME_SPEC.md ctx table.

7.2 Recall-gate helper S

  • ctx.thinkBeat({phraseSoFar, blankIndex, ms=1800, hintAfterMs}) — renders the standard "verse so far + pulsing blank" prompt overlay/strip, optionally speaks the phrase-so-far, resolves after the beat (or immediately on tap for impatient kids — the beat invites recall, never blocks). Provides the timed first-letter hint used by Slash. Used by Balloon, Firefly, Garden, Falling, Slash.

8. Recitation module — the ⭐⭐⭐ gate L

One screen (shell-level view, not a game module: #/b/<b>/<s>/recite/<v>, built in js/app.js + js/lib/recite.js), offering all four modes as big cards. Any mode's pass records stage 3, the recitation trophy, and mode+date. The reference is always part of the check — every mode ends with "…and say the reference!"

Mode 1 — 🧑‍🤝‍🧑 Grown-Up Check (the AWANA mirror)

Flow
Screen prompts "Hand me to a grown-up!" → adult sees the full verse + reference; kid recites; adult taps any word the kid missed (tapped words turn amber). Pass = 0 missed words (word-perfect bar) with a "so close!" celebratory retry otherwise — never a fail screen. A "reference ✓" chip must be tapped too.
Notes
No mic, no network, works everywhere; the strictest and most trustworthy mode. Sticker Quest's check-off (§5.1) is the K-friendly light version of this.

Mode 2 — 🎙️ Record & Hear Yourself

Flow
MediaRecorder captures the kid reciting (max 90 s) → playback side-by-side with the verse text + a "play the real one" button (read-file audio) → kid/parent taps "Word perfect! ✓" or "One more try". Recording is discarded after the session (privacy: nothing persisted, stated on-screen).
Notes
Self-monitoring via playback is genuinely effective (hearing your own gaps). Feature-detect MediaRecorder + mic permission; hide the card if unavailable.

Mode 3 — 🪄 Magic Ears (speech recognition — generous, never punishing)

Flow
Web Speech SpeechRecognition (feature-detected; card hidden where unsupported, e.g. Firefox; needs network on most platforms — say so on the card). As the kid recites, recognized words light the verse tiles green in order.
Generosity rules (hard requirements)
(a) Match on cleanWord + Levenshtein ≤ 1 (2 for words ≥ 6 letters); (b) skip-ahead window of 2 (a missed function word never stalls the lighting); (c) interim results count; (d) numbers in references match digits or words ("three sixteen"). (e) An unlit word is never marked wrong — after the attempt, unlit words simply stay unlit and the screen says "Say it again for the magic ears?" with a replay button. ≥ 90% lit + reference heard → offer "Word perfect! ✓" confirm (adult or kid taps).
Notes
SR mishears young voices constantly — the design treats SR as a light show over recitation, with the human confirm as the actual gate. Auto-stop listening after 10 s of silence.
Auto-award option (added post-launch at the owner's request)
A grown-ups toggle on the Magic Ears card (sparksArcade.magicEarsAuto): when ON, the star is awarded with no confirm tap — but only at a STRICTER bar than the manual path: every single word lit (100%, not 90%) plus the reference heard. Default OFF.

Mode 4 — 🏠 Said It at Club!

Flow
Honest self-report for verses recited at Sparks club or elsewhere: "Did you say it to your leader?" → date-stamped log, trophy awarded. One tap, no verification — trust the family (same trust model the app already uses everywhere).
